[1]How do releases work?

Our releases follow trunk-based development with short-lived feature branches and automated delivery from main. Plan against the roadmap, build behind feature flags, validate the pull request, then cut and monitor the release. Roll back to the previous stable tag if health checks regress.

[2]Deployment playbook

Merge into main only after unit, integration, end-to-end, and security checks pass. Observe the release before closing it.

[3]Slack: #releases — cadence

Ada: Minor releases ship weekly. Major releases remain monthly unless the roadmap marks an exception. Sam: Keep the rollback owner in the release checklist.

[4]Incident response playbook

When a release causes an incident, halt promotion, assign an incident lead, roll back, and preserve the evidence needed for the postmortem.
